Conclusion

Through this experiment, I successfully observed the Client-Server model in real-time. By utilizing Chrome Developer Tools, I monitored the HTTP network transactions and confirmed how headers coordinate request parameters and response values.

The essential HTTP Status Codes observed and documented are categorized as follows:

  • 1xx Informational:
    • 100 Continue: Indicates that the initial part of the request has been received by the server and the client should continue with the request.
  • 2xx Success:
    • 200 OK: The standard response for successful HTTP requests, indicating that the requested webpage or asset has loaded completely.
    • 201 Created: The request has been fulfilled and has resulted in the creation of a new resource on the server.
  • 3xx Redirection:
    • 301 Moved Permanently: This and all future requests should be directed to the newly provided web address.
    • 304 Not Modified: Indicates that the resource has not changed since the last request, allowing the browser to load it efficiently from cache instead of downloading it again.
  • 4xx Client Errors:
    • 400 Bad Request: The server cannot process the request due to a client-side error (e.g., malformed request syntax).
    • 401 Unauthorized: The request requires user authentication before accessing the resource.
    • 403 Forbidden: The server understood the request but refuses to authorize it (access is denied).
    • 404 Not Found: The requested resource or webpage could not be found on the server.
  • 5xx Server Errors:
    • 500 Internal Server Error: A generic error message given when an unexpected condition is encountered by the web server.
    • 502 Bad Gateway: The server was acting as a gateway or proxy and received an invalid response from the upstream server.
    • 503 Service Unavailable: The server cannot handle the request temporarily (usually due to overloading or maintenance).

Aim:

Explain Client-Server Architecture and observe HTTP Requests and Responses using Browser Developer Tools.

Program / Explanation:

Client-Server Architecture: It is a distributed application structure that partitions tasks or workloads between service providers (servers) and service requesters (clients). When you type a website URL in your browser (Client), it sends an HTTP Request to the web server, which processes it and sends back an HTTP Response (typically HTML, CSS, JS documents).

To inspect these interactions in Google Chrome / VS Code Live Server:

  1. Right-click anywhere on your web page and select Inspect (or press F12).
  2. Navigate to the Network tab.
  3. Reload the page (Ctrl + R or Cmd + R) to capture all HTTP activity.
  4. Click on any request line (e.g., experiment1.html) to examine the Request and Response Headers.
